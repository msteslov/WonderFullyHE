# Bootstrap: маршрут и контракты

Bootstrap должен обновлять шифротекст с сохранением сообщения при заданных
условиях точности, уровня, масштаба и безопасности. Публичный интерфейс —
`Bootstrapper` (`include/m2424/bootstrap.hpp`): `prepare`, `preflight`, `apply`.
Подготовка реализована в опциональной analysis-библиотеке; исполнение — в основной.

## Маршрут вычисления

Для пути со сгенерированным sparse-ключом последовательность стадий следующая:

```text
входной шифротекст под основным ключом s
  → encapsulation: переключение s → s_b
  → centered ModRaise: q_src → Q
  → CoeffToSlot:
      восстановление s_b → s внутри первого фактора
      HP- и LP-ветви
  → EvalRound каждой LP-половины
  → HP − (q_src / Delta0) · I_hat
  → SlotToCoeff
  → выходной шифротекст под ключом s
```

Снижение modulus и согласование масштабов задаются фактическим расписанием
подготовленного плана. Изменение scale в метаданных не является допустимой
заменой арифметической операции.

Полный sparse-маршрут в текущей реализации останавливается на проверке домена
EvalRound. Интеграционный K=1-сценарий существует отдельно как тестовое допущение.
Текущие ограничения сведены в [состоянии реализации](status.md).

## Семантика входа

После centered lift рассматриваются коэффициенты

```text
u = m + nu_b + q_src · I,
y = sigma(u / Delta0),
|I_j| <= K.
```

Здесь `Delta0` — исходный масштаб; `q_src` — точное произведение исходных
простых; `nu_b` включает ошибку до lift, в том числе encapsulation для sparse-пути.
Обычный `modRaiseToTop` не устанавливает K=1.

Для ключа фиксированного веса `h` сертификат выводит `K=h` из распределения
сгенерированного ключа и входных границ. Допустимые веса удовлетворяют `2<=h<=N`.
Выбор веса не служит доказательством конкретного уровня безопасности.

Ошибка восстановления ключа относится к входной семантической ошибке первого
фактора CtS. Она распространяется через обе ветви и не прибавляется повторно
к `nu_b`, домену LP или выходу bootstrap.

## Подготовка и исполнение

`BootstrapRequest` содержит целевой контракт, входные границы, параметры
арифметического расписания и внешние свидетельства безопасности.
`BootstrapPlan` хранит подготовленные стадии, общий `trace`, результат
`executionReadiness()` и план EvalRound.

Подготовка проверяет входной контекст, фактические primes, масштабы, необходимые
ключи, допустимость lift, локальные сертификаты и общий бюджет. Исполнение
использует подготовленные стадии без расшифровки и без получения границ
из наблюдаемых значений.

`executionReadiness()` отражает условия исполнимости стадий;
`trace().result` отражает общий результат. Локальный успех не отменяет отказ
по общему бюджету или отсутствию свидетельств. Отклонённый план не предоставляет
результат bootstrap; первая причина отказа сохраняется.

## Домен и бюджет ошибки

Нормировка LP включена в первый линейный фактор. Сертифицированный радиус:

```text
rho_cert = (M_m + M_nu_b) / q_src + E_LP < 1/2.
```

При отсутствии необходимой входной границы её значение остаётся `Unknown`.
Радиус до CtS является диагностикой и не заменяет `rho_cert`.

Планировщик резервирует выходной бюджет с учётом коэффициента усиления StC,
его собственной ошибки и арифметики объединения. Оставшаяся часть задаёт
допустимую ошибку восстановления целого в EvalRound. Неположительный остаток
означает отказ до компиляции или исполнения EvalRound.

Границы всех стадий должны относиться к одному фактическому расписанию.
Малая ошибка в тесте с расшифровкой не заменяет аналитическую верхнюю границу.

## Безопасность и тестовые допущения

`RlweSecurityEvidence` передаёт результаты внешнего оценивания, а не реализует
оценщик. Свидетельство должно соответствовать семейству, фактическому modulus,
составу публичного материала и заявленным предположениям. Общая оценка использует
минимум по необходимым семействам. Отсутствие одного свидетельства оставляет
общий уровень неизвестным. Оценка обычного SEAL-контекста не заменяет оценку
взаимосвязанных ordinary/sparse-ключей.

При наличии сгенерированных sparse-ключей планировщик выводит K из сертификата
и не использует заявленное вызывающей стороной значение. Без таких ключей
производственный путь не принимает `BootstrapLiftEvidence::Analytical`
как достаточное основание для K.

`TestFixtureAssumption` допускает интеграционное исполнение только в тестовой
сборке и исключает глобальную production-сертификацию. Отдельные диагностические
API восстановления sparse-ключа также доступны только при включённом тестировании.

Исходные точки проверки: планировщик (`src/planning/bootstrap_planner.cpp`),
исполнитель (`src/ckks/bootstrap.cpp`),
интеграционный тест (`tests/test_bootstrap_end_to_end.cpp`).
