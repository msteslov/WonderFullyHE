# Линейные преобразования

CoeffToSlot и SlotToCoeff связывают коэффициентное представление после ModRaise
с представлением, необходимым для нелинейной стадии. Порядок слотов соответствует
Microsoft SEAL. `CanonicalEmbeddingReference` задаёт независимый квадратичный
plaintext-эталон для проверки; он не используется как рабочий алгоритм.

## CoeffToSlot

`CoeffToSlotPlan` (`include/m2424/coeff_to_slot.hpp`) принимает `RaisedCipher`,
полученный из `modRaiseToTop`, и возвращает `slotCipherFirst` и `slotCipherSecond`:
две половины коэффициентного plaintext. Синтетическое DFT-преобразование обычных
CKKS-слотов не эквивалентно этому контракту.

Факторизация реализует canonical inverse embedding `U₀ᵀ/N` посредством
radix-2 special FFT, разреженной bit-reversal перестановки и объединения факторов.
Внутри сгруппированного фактора используется BSGS с double hoisting. Разложение
для baby-step rotations разделяется между операциями; накопление в расширенной
базе предшествует соответствующим ModDown. Plaintext-произведения суммируются
до единственного rescale фактора.

`prepare` создаёт неизменяемый `PreparedCoeffToSlotPlan`, связанный с контекстом,
входным `parms_id`, уровнем, масштабом и контрактом. `apply` повторяет проверки
совместимости. Кодирование констант выполняется на стадии подготовки.

Для `N=16384`, depth 4 зарегистрирован измеренный preset `{6,5,5,3}`.
Он задаётся явно; конструктор не выполняет скрытый подбор.
`estimateFactorizations()` использует модель поддержки диагоналей и не гарантирует
совпадения ранжирования с измерениями. `bench_coeff_to_slot` разделяет построение
контекста и плана, подготовку ключей и plaintext, первый и повторный вызовы.

## HP- и LP-ветви

`EvalRoundPlusCoeffToSlot` (`include/m2424/evalround_plus_coeff_to_slot.hpp`)
формирует две пары выходных половин:

```text
HP = u^(a) / Delta0 + eta_HP,
LP = I^(a) + (m^(a) + nu_b^(a)) / q_src + eta_LP.
```

Нормирующий множитель `alpha=Delta0/q_src` включается в диагонали первого
LP-фактора, включая фазовую коррекцию второй половины. Дополнительный отдельный
rescale для этой нормировки не требуется. Привязка prepared-плана включает
точный исходный масштаб и исходную базу primes.

Обычная подготовка (`prepare`) и сертифицирующая (`prepareCertified`)
различаются. Сертификация требует подтверждённых входных границ и реализуется
в analysis-библиотеке.

Для `SparseRaisedCipher` исполнитель первого фактора выполняет ровно одно
восстановление `s_b → s`, общее для четырёх HP/LP-выходов. Оно сохраняет modulus
и scale и не является отдельной стадией `Bootstrapper`. Остальные факторы
и заключительная проекция исполняются под основным ключом.

## Распространение границ

Для каждого фактора хранятся норма идеального оператора `kappa`, граница
возмущения `delta`, идеальная амплитуда `M`, входная семантическая ошибка `E`
и локальная арифметическая ошибка `B_local`:

```text
M_next <= kappa · M,
E_next <= kappa · E + delta · (M + E) + B_local.
```

В sparse-пути начальная `E` включает восстановление ключа. Этот член не входит
повторно в `B_local`. Локальные слагаемые включают необходимые оценки кодирования,
key switching, ModDown, rescale и представления масштаба.

Сертификат проверяет фактические primes и масштабы, а также запас до переполнения
центрированного представления. Неизвестные или заниженные обязательные границы
отклоняются. Протокол исполнения позволяет сопоставить стадии с сертификатом;
расшифровка для такого сопоставления выполняется только в тестовом эталоне.

## SlotToCoeff

`SlotToCoeffPlan` (`include/m2424/slot_to_coeff.hpp`) преобразует две половины
обратно в шифротекст. `applyPlain` и `applyPlainTrace` предоставляют математический
путь для проверки. `prepare` создаёт `PreparedSlotToCoeffPlan`; `preflight`
и `apply` проверяют и исполняют подготовленный план.

`SlotToCoeffContract` задаёт границы амплитуды и ошибки каждой половины,
а также допустимый support ошибки evaluation keys. Сертификат содержит
пофакторные оценки, расписание, ключевые требования, выходную ошибку и усиление
`gamma`. Сертифицирующая подготовка требует analysis-цели; исполнитель входит
в основную библиотеку.

При планировании полного bootstrap собственная ошибка StC и усиление входной
ошибки учитываются раздельно. Идеальная норма преобразования не подменяет
фактическое усиление подготовленного плана.

Проверки: сертификаты CtS (`tests/test_coeff_to_slot_cert.cpp`),
sparse CtS (`tests/test_sparse_coeff_to_slot.cpp`),
StC (`tests/test_slot_to_coeff.cpp`).
Подробные выводы и численные условия сохранены в
[архиве исследований](archive/README.md).
