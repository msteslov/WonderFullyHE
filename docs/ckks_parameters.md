# CKKS-параметры

Проект использует Microsoft SEAL как CKKS-движок. Готовые параметры вынесены в публичный модуль `m2424::profiles`, чтобы пользователь не собирал CKKS-настройки вручную.

- `fast_demo_ckks` — быстрый профиль для локальной проверки сборки и простых экспериментов.
- `basic_ckks` — основной профиль для demo, ABFT и benchmark базовых операций.
- `balanced_ckks` — профиль на `N = 8192` с дополнительным уровнем умножения.
- `depth_ckks` — профиль для анализа вычислительной глубины и bootstrapping-блоков.
- `high_precision_ckks` — профиль с `scale = 2^50`, когда важнее точность, чем скорость и размер.

Актуальная таблица профилей формируется командой:

```bash
./build/demo_profile_report
```

| Профиль | N | Слоты | Биты коэффициентных модулей | Суммарный размер, бит | Масштаб | log2(scale) | Оценка глубины умножений |
|---|---:|---:|---|---:|---:|---:|---:|
| `fast_demo_ckks` | 4096 | 2048 | `40-30-30` | 100 | `1.07374e+09` | 30 | 1 |
| `basic_ckks` | 8192 | 4096 | `60-40-40-60` | 200 | `1.09951e+12` | 40 | 2 |
| `balanced_ckks` | 8192 | 4096 | `50-40-40-40-48` | 218 | `1.09951e+12` | 40 | 3 |
| `depth_ckks` | 16384 | 8192 | `60-40-40-40-40-60` | 280 | `1.09951e+12` | 40 | 4 |
| `high_precision_ckks` | 16384 | 8192 | `60-50-50-50-60` | 270 | `1.1259e+15` | 50 | 3 |

## Масштаб

В основных профилях используется масштаб:

```text
scale = 2^40 ~= 1.0995 * 10^12
```

Такой масштаб удобен для приближённых вычислений над вещественными числами в CKKS и согласуется с 40-битными промежуточными коэффициентными модулями.

Для быстрых демонстраций используется `2^30`, потому что профиль `fast_demo_ckks` рассчитан на меньшие 30-битные промежуточные модули. Для `high_precision_ckks` используется `2^50`: это снижает ошибку округления при кодировании и rescale, но увеличивает стоимость операций и требует более крупного `N`.

После умножения двух ciphertext масштаб примерно возводится в квадрат:

```text
2^40 * 2^40 = 2^80
```

Затем `rescale_to_next` делит результат на ближайший 40-битный модуль и возвращает масштаб близко к `2^40`. При этом расходуется один уровень modulus chain.

## Цепочка модулей

Быстрый профиль:

```text
coeff_modulus_bits = {40, 30, 30}
total = 100 bits
```

Он нужен для коротких локальных запусков и одного уровня умножения. Для содержательных benchmark-выводов используется не он, а `basic_ckks` или `depth_ckks`.

Базовый профиль:

```text
coeff_modulus_bits = {60, 40, 40, 60}
total = 200 bits
```

Внутренние 40-битные модули задают практический бюджет для операций `mul + rescale`. 60-битные модули используются на границах цепочки.

Сбалансированный профиль:

```text
coeff_modulus_bits = {50, 40, 40, 40, 48}
total = 218 bits
```

Он остаётся на `N = 8192`, но использует весь доступный `tc128`-бюджет для этой степени. Практический смысл — получить третий уровень `mul + rescale` без перехода на более тяжёлый `N = 16384`.

Профиль для анализа глубины:

```text
coeff_modulus_bits = {60, 40, 40, 40, 40, 60}
total = 280 bits
```

В этом профиле больше внутренних 40-битных уровней, поэтому он поддерживает больше последовательных умножений. Увеличение суммарного размера коэффициентного модуля требует большего `poly_modulus_degree`, поэтому для этого профиля используется `N = 16384`, а не `N = 8192`.

Профиль высокой точности:

```text
coeff_modulus_bits = {60, 50, 50, 50, 60}
total = 270 bits
```

Он использует `scale = 2^50` и 50-битные промежуточные модули. Такой профиль нужен, когда ошибка результата важнее скорости, например для сравнения точности разных вычислительных цепочек.

## Слоты

CKKS упаковывает значения в слоты. В Microsoft SEAL число слотов равно:

```text
slots = N / 2
```

Для текущих основных степеней:

```text
8192 / 2 = 4096 slots
16384 / 2 = 8192 slots
```

Профиль `fast_demo_ckks` использует `4096 / 2 = 2048` слотов.

## Как выбирать профиль

| Задача | Рекомендуемый профиль |
|---|---|
| Быстро проверить сборку или пример | `fast_demo_ckks` |
| Обычные demo, ABFT, защищённая статистика | `basic_ckks` |
| Нужен ещё один уровень умножения без перехода на `N = 16384` | `balanced_ckks` |
| Анализ глубины, bootstrapping-блоки, длиннее цепочка умножений | `depth_ckks` |
| Приоритет точности, а не скорости | `high_precision_ckks` |

## Эксперимент с глубиной

`demo_noise_growth` использует профиль `depth_ckks` и последовательно возводит ciphertext в квадрат:

```text
x -> x^2 -> x^4 -> x^8 -> x^16
```

После каждого успешного умножения `chain_index` уменьшается. На текущем профиле следующий шаг к `x^32` завершается ошибкой `scale out of bounds`, потому что доступные уровни умножения уже израсходованы.

Этот эксперимент задаёт базовую точку для bootstrapping-модуля: после исчерпания уровней дальнейшее ciphertext-ciphertext умножение требует обновления ciphertext.

## Проверка параметров

Профили проходят проверку параметров Microsoft SEAL при вызове `SealAdapter::create`. Выбор параметров балансирует три величины:

- доступную мультипликативную глубину;
- численную точность после rescale;
- степень полиномиального модуля, требуемую выбранным коэффициентным модулем.
